  NEW LAW-GRADE BUG CLASSES found on the way (all fixed, all general):
    1. THE IQ4_XS NIBBLE LAW: elements 0-15 of a 32-group = LOW nibbles of bytes
       0-15; elements 16-31 = HIGH nibbles. Byte index = (l & 15), high/low by
       (l >> 4) -- NOT byte (l >> 1) by parity. (Cost: run-1 all-wrong; the CPU
       kernel-semantics simulator caught it in minutes.)
    2. THE UNSIGNED-SUBTRACT TRAP: (x & 0xFu | y << 4) - 32 in C UNSIGNED
       arithmetic WRAPS to ~4.29e9 for x < 32. The llama.cpp reference casts to
       int8_t BEFORE subtracting; hand kernels MUST (int)(...) - 32.
    3. THE PAIR-VS-POS LAW: gx up-kernels consume the SHARED hn (pos-addressed,
       8 pairs -> 1 row); the dn consumes PER-PAIR moe_act [NPAIR][512]
       (pair-addressed). A P=1 test cannot distinguish them -- the slice (P=3)
       is the minimum discriminating shape (exactly one good pair per position).
    4. hrot-style drift kernels stamp their FULL row range: an [88][2048]-writer
       over a [3][2048] buffer = 680KB OOB per replay -> progressive-corruption
       device fault at ~256 replays (run-1 S3g). Buffers must be sized to the
       MUTATOR, not the consumer.
