NEW PLATFORM LAWS FOUND (the D3 fault forensics, ~15 boots):
  1. THE NAME LAW (the big one): the TinyELF/program name MUST equal the cubin's
     kernel SYMBOL. A mismatch (e.g. file-prefix name) silently skips the
     .nv.info parse (maxntid/stack unparsed) and the launch faults with SM
     "Illegal Instruction Encoding" on ALL GPCs. Every historical clean run had
     matching names; every faulting run had a prefixed name. 100% correlation.
  2. SINGLE-ARG SIZE CAP: hand-NVProgram buffer args >~457MB-1.16GB fault (same
     signature). 457MB/arg x 8 args clean; 8GB/3.66GB/2.38GB/1.16GB single args
     fault. Engine's proven hand-kernel arg class = 183MB (packed per-block) —
     per-layer routed banks (373MB) are legal.
  3. VA POINTER TABLES ARE LEGAL (ptbl of absolute 64-bit VAs read from device
     memory works) — the earlier "pointer-chase illegal" reading was an artifact
     of law 2. Duplicate buffer args suspected bad (1 datapoint) — avoid.
  4. GPU-process exit -> GPU-EXIT reboot held 5/5 this session (also on CLEAN
     exits). One GPU python process per boot; batch everything into it.
  5. THE QUEUE FAULT (open): NVComputeQueue-replayed [wait->exec(gx)->signal]
     wedges on the first wait even though eager gx is clean and gcycle's own
     queues run 452-kernel graphs daily. Mechanism unknown — P1 item #1.
